# Textual holdings corpus (866 $a text only)
# ==========================================
#
# 110 unique 866 $a statements, collected by hand while the original monolithic
# parsing regex was being written, and kept because between them they cover far
# more caption and chronology styles than the synthetic .mrc fixtures in this
# directory do. Most of them the old monolith parsed; a few it never did.
#
# This is 866 $a TEXT, not MARC. It exercises holdings_parser.parse_866(),
# marc_converter.convert_holdings() and pattern_detector.detect_patterns()
# directly, and says nothing about record-level behaviour -- $8 linking, 853
# conformance, multiple 866s on one record. data/messy_holdings.mrc remains the
# fixture for that.
#
# Provenance: transcribed from real catalogue records. It carries no patron
# data, no local identifiers and no institutional codes -- only enumeration and
# chronology strings and, in the section headings, publicly known serial titles.
# It is committed as .txt deliberately; .gitignore's *.mrc rule keeps real
# holdings FILES out of the repository and is not weakened by this file.
#
#
# FORMAT
# ------
# One statement per line, in source order, grouped by the section headings the
# original file carried. Duplicates are removed; "[x2]" records how many times a
# statement appeared. Lines starting with "#" are comments, "[section: name]"
# opens a section, and a trailing "  # status:ID" is this statement's currently
# known outcome. No holdings statement in this corpus contains "#", so splitting
# a line on it is unambiguous.
#
#   (no tag)  parses and converts with nothing lost
#   loss:Dn   converts, but silently drops values the statement asserts
#   fail:Dn   produces no 853/863 at all
#   warn:Dn   converts, and warns about what it dropped
#   known:Dn  a deliberate, documented limitation, not a defect
#
# The Dn ids are defined in CORPUS-FINDINGS.md. Regenerate every count in that
# file with:
#
#     python scripts/corpus_report.py
#
# The tags record what the tools do TODAY. They are a baseline to notice change
# against, not a specification -- when a fix lands, the report will disagree
# with the tag, and the tag is what should be updated.
#
